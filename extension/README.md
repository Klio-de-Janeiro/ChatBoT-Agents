# MultiChat Agent: Chrome extension

Рабочая сборка MV3 находится в `dist/`. Расширение подключается к Native Messaging host `com.multichat.agent`; установка Python host описана в корневом README. Wire interface: [CONTRACT.md](CONTRACT.md).

## Первый запуск

1. Из `extension/` выполнить `npm ci` и `npm run build` (Node.js 22+).
2. В **том же профиле Chrome, где выполнен вход в сервисы**, открыть `chrome://extensions`, включить режим разработчика и загрузить распакованное расширение из `extension/dist`.
3. Зарегистрировать Native Messaging host с ID именно этого расширения согласно корневому README.
4. Нажать кнопку расширения → отметить DeepSeek и/или Qwen → **Сохранить**. По умолчанию оба выключены; это явный выбор разрешённых доменов. В диагностике видны ID расширения и состояние соединения с host.
5. Вручную открыть и авторизовать выбранные сервисы: `https://chat.deepseek.com/`, `https://chat.qwen.ai/`. После установки расширения перезагрузить эти вкладки. Оставить хотя бы одну авторизованную вкладку каждого нужного сервиса открытой.
6. Отправить задание через CLI. Расширение создаст отдельную неактивную вкладку для каждой пары `provider + conversation_key`. Пользовательские чаты только проверяются на наличие признака авторизации; запросы в них не отправляются.

## Где менять код

| Файл                | Назначение                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `src/config.ts`     | CSS-селекторы и время стабилизации DOM; их также можно изменить в options без пересборки |
| `src/dom.ts`        | Ввод, точное сопоставление нового prompt и assistant, признаки завершения                |
| `src/engine.ts`     | Durable request states, защита от дублей, очереди и карантин                             |
| `src/browser.ts`    | Выбор/создание вкладок и проверка отправителя                                            |
| `src/background.ts` | Native Messaging и восстановление после перезапуска                                      |
| `src/protocol.ts`   | Wire validation, ограничения и фиксированный allowlist                                   |

Селекторы — предварительные кандидаты. Текущий авторизованный DOM реальных сервисов не проверен: см. [PROVIDERS.md](PROVIDERS.md). При `DOM_UNSUPPORTED`, `LOGIN_OR_DOM_REQUIRED` или `SEND_CONTROL_MISSING` проверьте элементы страницы в DevTools и измените JSON в options. `signedIn` должен выбирать видимый элемент авторизованного аккаунта; `user`/`assistant` — контейнеры соответствующих сообщений, `text` — содержимое сообщения без кнопок, `complete` — признак завершения внутри конкретного ответа. Широкий селектор вроде `div` для этих полей нарушает сопоставление; не используйте его.

После неоднозначной отправки беседа помещается в карантин. Для `unknown`/`timeout` сначала вручную проверьте выделенную вкладку. Автоматического повтора нет. Не используйте новый request_id для повторной отправки того же запроса до проверки. Частичный ответ при прерванной выдаче сохраняется как неполный; успешным считается только `completed`.

После закрытия выделенной вкладки, ручной навигации или полного перезапуска браузера продолжение той же беседы требует ручной проверки и нового conversation_key. Это ограничение MVP защищает от попадания в чужую вкладку при повторном использовании Chrome tab ID. Не очищайте данные расширения для исправления ошибки: это удаляет durable защиту от дублей.

## Проверки

```powershell
npm ci
npx playwright install chromium
npm test
```

`npm run test:unit` проверяет протокол, durable состояния, очереди и авторизацию отправителя. `npm run test:browser` загружает настоящую MV3-сборку в отдельный тестовый Chromium, запускает локальные HTTPS-страницы и подменяет только Native Messaging port тестовым harness. Cookies и существующие профили пользователя не читаются и не копируются. Привязка доменов к локальному серверу и отключение проверки тестового TLS действуют только в этом процессе Chromium; системные DNS/hosts и хранилище сертификатов не меняются. OS-регистрация native host и реальные ответы сервисов этим тестом не проверяются.

`npm test` также запускает `tests/live-dom.mjs`: структурные примеры DOM, наблюдавшиеся у DeepSeek и Qwen, и замену кнопки React во время ожидания сохранения перед отправкой. Это локальные тесты, не подтверждение полного цикла через авторизованные сервисы. Диагностика `DOM_TIMEOUT` содержит ревизию адаптера, этап ожидания, счётчики найденных сообщений и признаки завершения/генерации; тексты сообщений в неё не включаются.

`npm run inspect:providers` — отдельная необязательная read-only проверка публичных неавторизованных страниц в новом Chromium. Отчёты и временные тестовые профили находятся в игнорируемом `work/`. `npm run format` форматирует исходники; `npm run format:check` проверяет формат.

История request_id и ответы в extension storage не удаляются автоматически: иначе нельзя гарантировать дедупликацию. Разрешение `unlimitedStorage` снимает обычную квоту Chrome 10 MiB для этого локального durable кеша; данные остаются на диске данного профиля. При ошибке записи, в том числе нехватке диска, новые отправки блокируются. Явная очистка старых тел ответов с сохранением tombstone ID остаётся будущим улучшением. Native host не должен повторять неоднозначные команды автоматически.
