# Extension MVP wire agreement

Implements the root `../CONTRACT.md` (wire version 1); does not alter backend or docs ownership.

Native host: `com.multichat.agent`. On connection: `{ "type": "hello", "version": 1 }`.
Inbound: `{ "type":"job", "request_id":"UUID", "provider":"catalog ID", "prompt":"nonempty string", "conversation_key":"task:provider:role", "timeout_ms":180000, "operation":"ask|open", "modes":{"think":true,"search":false} }`. Version 0.2.0 adds optional operation/modes, defaulting to ask/empty. Open still carries a nonempty internal prompt sentinel, which is never entered or submitted. Completed open results may have empty text; completed ask results must remain nonempty. Mode maps have at most 16 lower snake/kebab keys (`^[a-z][a-z0-9_-]{0,31}$`), boolean or nonblank string values up to 100 characters. Unknown payload keys are rejected.
Outbound: `{ "type":"result", "request_id":"UUID", "status":"completed|failed|timeout|needs_user_action|unknown", "text":"", "markdown":"", "content":{}, "conversation_url":"https://... or empty", "error":"CODE: diagnostic" }`. Version 0.3.0 adds optional `markdown` and `content`. `markdown` is the answer in the provider's own dialect — what its "copy answer" control yields, including tables, task lists, nested lists, fenced code with the original info string and `$...$`/`$$...$$` math. `content` is `{version:1, plain, blocks:[{type:"heading|paragraph|list|quote|table|code|math|image|rule",...}]}` with forward-compatible extra keys per block; image bodies are never embedded, `src` stays as the page exposed it, and a missing resource never fails the capture. Both are additive: `text` is still the compatibility contract, an empty capture is omitted, and a malformed or oversized one (`markdown` > 4 MiB or `content` > 2 MiB UTF-8, wrong block shape) invalidates the result exactly like other invalid page results. Rich capture must never delay or block completion: any conversion error degrades to text-only.
Completed results have complete answer text. A timeout/provider interruption can include correlated partial text (capped at 500000 UTF-16 characters); store it as raw output and never treat it as completed. Prompt max 900 KiB UTF-8; full serialized inbound job max 1 MiB UTF-8; outbound result max 8 MiB UTF-8. Timeout 1..3600000 ms, conversation_key 1..512 characters. Invalid input with a valid request_id returns failed/INVALID_JOB; uncorrelatable messages are ignored and diagnosed locally. Unknown keys are rejected. Duplicate request IDs never submit again; same ID with different input returns failed/REQUEST_ID_CONFLICT. Terminal results may be replayed on host reconnect (host must accept results idempotently). Host must not retry ambiguous delivery under a fresh ID.

Durability: the extension persists a request reservation before any tab work and persists `sent` BEFORE dispatching a DOM submission. On service-worker restart, unfinished requests become `unknown` (even if not actually clicked); this is deliberately conservative. A timed out or ambiguous conversation is quarantined. Its tab is never reused for more jobs. Storage write failure prevents submission. Records/tombstones are not automatically pruned; clearing extension storage removes duplicate protection. Disconnect never triggers resubmission.

One dedicated active tab in an owned normal Chrome window per exact provider + conversation_key, reused only while tab session ownership and exact conversation URL match. Work windows stay visible and must not be minimized; Chrome chooses OS-valid bounds with no fixed coordinates or dimensions. Existing user tabs are never submitted to, navigated or refreshed. A normal allowlisted provider tab must already exist in this profile; authentication is then verified in the fresh owned window, so source scripts invalidated by extension reload are harmless. Positive account/history evidence may be collapsed or hidden; the composer must be visible and any visible login/challenge still blocks. The owned URL must remain at the provider root with no detected history/draft before initial readiness; restored conversation routes are rejected. No cookies, login automation or undocumented chat APIs. Tab closures, navigation, drafts, extra messages, CAPTCHA, login and quota cause explicit diagnostics. Providers execute concurrently; each conversation and tab are serialized. DeepSeek DOM replacements are accepted only when the captured virtual-list row identity stays the same; identity changes or replacement without a stable identity remain ambiguous.

Mode controls are editable data in `src/mode-controls.ts` and provider options JSON. Supported defaults: DeepSeek boolean think/search; Qwen boolean think/search and string reasoning=auto|thinking|fast (think and reasoning together are rejected). Requested names/values and observable states are validated before any changes or composer input. Search runs before thinking; every requested state is checked again after changes settle. Unsupported controls/states, ignored activation and partial failures return needs_user_action with a precise diagnostic before any prompt input or submission. No blind repeat toggles or automatic rollback. Mode defaults omitted by the caller remain untouched. The duplicate fingerprint includes defaulted operation and sorted mode keys; legacy four-field request tombstones remain compatible only with ask plus empty modes.

The provider catalog supplies the origin allowlist at build time. The user must enable each desired provider in the extension options. Provider JSON can change CSS selectors and timing, never origins or executable code. Completion requires the exact new user prompt, a captured new assistant message after it, a provider completion marker, no generating indicator, and stable nonempty response text. A generic elapsed sleep alone never means success.

Local tests replace only the browser native port with a test harness and intercept these exact origins with realistic local mock pages. They prove transport/state/DOM behavior, not live provider compatibility or OS native-host installation. Current DOM evidence and live limitations are recorded in `PROVIDERS.md`.
