# Extension MVP wire agreement

Implements the root `../CONTRACT.md` (wire version 1); does not alter backend or docs ownership.

Native host: `com.multichat.agent`. On connection: `{ "type": "hello", "version": 1 }`.
Inbound: `{ "type":"job", "request_id":"UUID", "provider":"deepseek|qwen", "prompt":"nonempty string", "conversation_key":"task:provider:role", "timeout_ms":180000 }`.
Outbound: `{ "type":"result", "request_id":"UUID", "status":"completed|failed|timeout|needs_user_action|unknown", "text":"", "conversation_url":"https://... or empty", "error":"CODE: diagnostic" }`.
Completed results have complete answer text. A timeout/provider interruption can include correlated partial text (capped at 500000 UTF-16 characters); store it as raw output and never treat it as completed. Prompt max 900 KiB UTF-8; full serialized inbound job max 1 MiB UTF-8; outbound result max 8 MiB UTF-8. Timeout 1..3600000 ms, conversation_key 1..512 characters. Invalid input with a valid request_id returns failed/INVALID_JOB; uncorrelatable messages are ignored and diagnosed locally. Unknown keys are rejected. Duplicate request IDs never submit again; same ID with different input returns failed/REQUEST_ID_CONFLICT. Terminal results may be replayed on host reconnect (host must accept results idempotently). Host must not retry ambiguous delivery under a fresh ID.

Durability: the extension persists a request reservation before any tab work and persists `sent` BEFORE dispatching a DOM submission. On service-worker restart, unfinished requests become `unknown` (even if not actually clicked); this is deliberately conservative. A timed out or ambiguous conversation is quarantined. Its tab is never reused for more jobs. Storage write failure prevents submission. Records/tombstones are not automatically pruned; clearing extension storage removes duplicate protection. Disconnect never triggers resubmission.

One dedicated active tab in an owned normal Chrome window per exact provider + conversation_key, reused only while tab session ownership and exact conversation URL match. Work windows stay visible and must not be minimized; their placement avoids fully covering the other provider's window. Existing user tabs are probed solely for signed-in evidence and are never submitted to or navigated. A work window is created only after an already open, authenticated, non-incognito provider tab is found. Its URL must remain at the provider root with no detected history/draft before first submission; restored conversation routes are rejected. No cookies, login automation or undocumented chat APIs. Tab closures, navigation, drafts, extra messages, CAPTCHA, login and quota cause explicit diagnostics. Providers execute concurrently; each conversation and tab are serialized. DeepSeek DOM replacements are accepted only when the captured virtual-list row identity stays the same; identity changes or replacement without a stable identity remain ambiguous.

Only https://chat.deepseek.com and https://chat.qwen.ai are compiled into the origin allowlist. The user must enable each desired provider in the extension options. Provider JSON can change CSS selectors and timing, never origins or executable code. Completion requires the exact new user prompt, a captured new assistant message after it, a provider completion marker, no generating indicator, and stable nonempty response text. A generic elapsed sleep alone never means success.

Local tests replace only the browser native port with a test harness and intercept these exact origins with realistic local mock pages. They prove transport/state/DOM behavior, not live provider compatibility or OS native-host installation. Current DOM evidence and live limitations are recorded in `PROVIDERS.md`.
