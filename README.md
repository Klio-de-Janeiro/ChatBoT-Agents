# Multi-Chat Agent — Windows MVP

Локальный оркестратор веб-чатов DeepSeek и Qwen: Codex составляет план, авторы готовят части материала, отдельный веб-редактор проверяет **все** ответы и возвращает структуру документа. Python собирает `.ipynb` или `.md`, не выполняя сгенерированный код. Есть прямой запрос одному провайдеру из терминала.

Используются открытые пользователем веб-интерфейсы в Chrome; ключи и API чат-ботов не нужны. Авторизация, CAPTCHA и ограничения сервиса остаются под контролем пользователя. При обычной работе Codex получает только JSON-статусы и пути к файлам: содержимое ответов и замечания редактора в его контекст не поступают.

## Статус и границы проверки

Это MVP, а не гарантия совместимости с любой версией сайтов. Локальные тесты проверяют очередь, сборку файлов, протокол и DOM-автоматизацию на mock-страницах. Они не подтверждают успешный реальный запрос DeepSeek/Qwen. Актуальные наблюдения и ограничения провайдеров — в [`extension/PROVIDERS.md`](extension/PROVIDERS.md).

Для живой проверки нужны установленный **Google Chrome**, вручную загруженное расширение, включённые провайдеры и вход пользователя на обоих сайтах. Наличие Edge или Chromium в Playwright не означает установку расширения в реальный Chrome. Скрипты не устанавливают расширение скрытно и не меняют политики Chrome.

## Установка

Нужны Windows, Python **3.11+**, Node.js **20+** с npm, Google Chrome **120+** и .NET Framework 4.x с `csc.exe`. На обычной Windows компилятор доступен в `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` либо в `Framework`. Если он отсутствует, сборка выдаст явную ошибку.

Откройте PowerShell. Во всех примерах путь проекта фиксирован; при переносе замените его целиком:

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\MultiChatAgent'
& .\scripts\bootstrap.ps1 -InstallSkill
```

Bootstrap создаёт `.venv`, устанавливает пакет editable и зависимости для разработки, собирает Windows native launcher `.exe`, устанавливает npm-зависимости, собирает расширение, запускает Python/extension/installation tests и устанавливает skill. Python вызывается по абсолютному пути, активация venv не нужна. `npm.cmd` используется для совместимости с PowerShell. Параметр `-Python 'C:\Path\python.exe'` позволяет выбрать интерпретатор, `-SkipTests` пропускает тесты, но не сборку. Bootstrap не регистрирует native host и не загружает расширение в Chrome. Сборка launcher использует `-CompileOnly`: готовый exe появляется в `.venv\native-host`, а конфигурация origin и manifest создаются при регистрации фактического ID ниже; существующая конфигурация при bootstrap сохраняется.

Если browser tests сообщают, что Playwright Chromium не установлен, установите его и повторите bootstrap:

```powershell
Push-Location '.\extension'
npx.cmd playwright install chromium
Pop-Location
```

Это тестовый браузер. Рабочий Chrome установите обычным способом отдельно, если его нет.

### 1. Загрузите расширение в Chrome

1. Откройте `chrome://extensions`, включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение**, выберите `C:\Users\User\Documents\ChatGPT\MultiChatAgent\extension\dist`.
3. Скопируйте ID расширения: ровно 32 строчные буквы от `a` до `p`.
4. Откройте параметры расширения через его значок либо страницу расширений. По умолчанию `enabled: []`: **ни один провайдер не включён**. Отметьте нужные `deepseek` и `qwen`, нажмите **Сохранить**.

Расширение запрашивает `nativeMessaging`, `storage`, `unlimitedStorage`, `tabs`, `alarms` и доступ только к `https://chat.deepseek.com/*` и `https://chat.qwen.ai/*`. `unlimitedStorage` нужен для сохранения ответов и защиты от дублей без стандартного лимита локального хранилища расширения. Настройки селекторов не могут расширить список доменов или добавить исполняемый код.

### 2. Зарегистрируйте native host для фактического ID

Подставьте ID, полученный в Chrome, вместо текста-заглушки:

```powershell
& .\scripts\install_native_host.ps1 -ExtensionId 'ID_ИЗ_CHROME'
```

Скрипт отклоняет любой ID, не соответствующий `[a-p]{32}`. Он компилирует `.venv\native-host\mca-native-host.exe`, пишет конфигурацию и manifest без BOM и создаёт **один** ключ текущего пользователя:

```text
HKCU\Software\Google\Chrome\NativeMessagingHosts\com.multichat.agent
  (Default) = C:\Users\User\Documents\ChatGPT\MultiChatAgent\.venv\native-host\com.multichat.agent.json
```

Manifest разрешает только `chrome-extension://ВАШ_ID/`. Для этого не нужны права администратора. Если этот host уже указывает на другой manifest, установка остановится; `-Force` явно заменяет регистрацию. `-WhatIf` показывает действие без изменений. `-PrepareOnly` собирает exe и manifest, **не меняя реестр**. После переноса проекта или изменения ID повторите регистрацию. Во время пересборки отключите расширение, если Windows сообщает, что exe используется.

Почему `.exe`: manifest указывает на скомпилированный Windows launcher, который запускает абсолютный `.venv\Scripts\python.exe -u -m multi_chat_agent native-host`. Потоки передаются как байты, без декодирования и замены переводов строк; диагностика идёт только в stderr. Аргументы Chrome — origin и `--parent-window` — не передаются парсеру CLI. `.bat`/`.ps1` не используются как native executable; их запуск зависит от shell-механизма и не является проверенным механизмом этого проекта. Требования к регистрации и протоколу описаны в [документации Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).

### 3. Войдите в сервисы и проверьте подключение

1. В том же обычном профиле Chrome откройте [DeepSeek](https://chat.deepseek.com/) и [Qwen](https://chat.qwen.ai/), войдите вручную.
2. Оставьте по авторизованной вкладке каждого нужного провайдера. Расширение использует их для проверки входа, а задания отправляет в собственные отдельные вкладки. Одна роль/беседа не смешивается с другой.
3. Перезагрузите расширение на `chrome://extensions`. В его параметрах обновите диагностику: `connected` должно стать `true`. Там же видны фактический `extension_id` и последняя ошибка.
4. Проверьте CLI:

```powershell
.\mca.ps1 doctor
```

`doctor` проверяет локальную среду/очередь и подключённые host-процессы; он не подтверждает актуальность селекторов сайтов или правильность входа в них. Если host не подключён, возвращаются `status: needs_user_action`, `browser_bridge_ready: false`, подсказка `next_action` и код выхода 1. Одного открытия вкладок DeepSeek/Qwen недостаточно: требуется загрузить именно расширение MultiChat Agent и зарегистрировать его native host.

## Работа из терминала

Из корня проекта используйте `mca.ps1`: он передаёт аргументы локальному venv Python без активации окружения. Для запуска из другой директории укажите полный путь к wrapper. Codex skill вызывает абсолютный путь самого интерпретатора.

### Прямой запрос

```powershell
.\mca.ps1 ask deepseek --prompt 'Объясни смысл транзакции SQLite на коротком примере.' --wait
```

Сохранится исходный ответ; stdout содержит только JSON-сводку с состоянием и путём. Редактор в режиме `ask` не вызывается. Пример с параметрами: `examples\direct-ask.ps1 -Provider deepseek -Prompt 'Ваш вопрос'`. Ответ можно открыть самостоятельно по возвращённому пути; skill не читает его в контекст Codex.

Для длинного промпта вместо `--prompt` используйте `--prompt-file 'C:\Path\prompt.txt'` (UTF-8). Параметр `--task-id` задаёт устойчивый ID прямого запроса; без него каждый `ask` создаёт новую задачу.

### Notebook: два автора и отдельный редактор

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\MultiChatAgent'
.\mca.ps1 run .\examples\notebook.plan.json --wait
```

В примере DeepSeek готовит теорию линейной регрессии, Qwen — практику. Затем отдельная редакторская беседа Qwen получает оба ответа и проверяет содержание, формулы, код и согласованность. Результат — `results\linear-regression.ipynb`. Код в notebook не запускается.

Для Markdown:

```powershell
.\mca.ps1 run .\examples\markdown.plan.json --wait
```

Результат — `results\sqlite-queue.md`. При создании нового задания выберите новый `task_id`: он обозначает сохранённую задачу, а не каждый повтор проверки статуса.

### Статус и ожидание

```powershell
.\mca.ps1 status linear-regression-notebook-001
.\mca.ps1 --help
```

`run`/`ask` сохраняют задание, `--wait` ведёт планировщик до конечного состояния. Без `--wait` запускается отдельный скрытый scheduler-процесс; `status TASK_ID --wait` позволяет дождаться существующей задачи, не создавая новую. `--wait-timeout 30` ограничивает только ожидание CLI: код выхода `3` означает, что задача может продолжаться в фоне. Этот worker не является службой Windows и не запускается автоматически после перезагрузки; возобновите существующую задачу через `status TASK_ID --wait`. При `unknown` или неопределённой доставке сначала проверьте беседу вручную: новый запрос может продублировать сообщение. Переподключение worker/host не является разрешением повторно отправить запрос.

## Формат плана

Формальная договорённость — [`CONTRACT.md`](CONTRACT.md), проверка — `src/multi_chat_agent/models.py`.

| Поле | Значение |
|---|---|
| `task_id` | Уникальный безопасный компонент пути; используйте буквы ASCII, цифры, `_`, `-` |
| `objective` | Общая цель и требования к итоговому материалу |
| `jobs` | Авторские задания: уникальные `id`, `provider`, `prompt`, `depends_on`, `timeout` |
| `depends_on` | ID необходимых предшественников; неизвестные ID и циклы запрещены |
| `timeout` | Время задания в секундах; в примерах 180, редактору 300 |
| `editor` | Отдельная роль редактора; для проверенного результата задайте её явно |
| `output` | `format: "ipynb"` или `"markdown"`, `path` к итоговому файлу |

Для воспроизводимого размещения используйте абсолютный `output.path`. Относительный путь считается **от каталога JSON-плана**, а не рабочей директории терминала. В примерах `../results/...` помещает результат в `results` корня проекта. Передача результатов зависимостей и всех ответов редактору выполняется backend, без участия Codex.

Редактор обязан вернуть JSON следующего вида; допустима внешняя ограда ```json:

````text
{"cells":[{"cell_type":"markdown","source":"# Заголовок\nОбъяснение"},{"cell_type":"code","source":"print(1 + 1)"}]}
````

`source` — строка, тип ячейки — `markdown` либо `code`. Не нужны `outputs` и `execution_count`. Для Markdown удобно запросить только Markdown-ячейки. Некорректный ответ сохраняется для пользователя; допускается не более одного запроса исправления формата редактору. Неисправимый ответ означает ошибку, а не успешно созданный notebook. `nbformat` проверяет структуру файла; это не доказательство математической корректности или безопасности кода.

## Skill Codex

Исходник: `.agents\skills\use-chat-bots`. Установка отдельно от bootstrap:

```powershell
& .\scripts\install_skill.ps1
```

Skill появляется в `C:\Users\User\.codex\skills\use-chat-bots`. Перезапустите/обновите чат Codex, если список skills уже был загружен. Пример обращения: «Используй `$use-chat-bots`, подготовь notebook по линейной регрессии: DeepSeek и Qwen — авторы, отдельный Qwen — редактор».

Skill записывает план, вызывает CLI через абсолютный venv Python, читает только сводку и возвращает ссылку на файл. Содержимое ответов, редакторских замечаний и финального документа он не открывает. Установщик оставляет `.mca-skill-install.json` с путями и признаком владения. Существующий skill без этого признака либо от другой установки не перезаписывается. Для нового местоположения используйте явный `-SkillDirectory`.

## Архитектура и надёжность

```text
Codex → plan.json → Python CLI / scheduler → SQLite command queue
                                              ↕
Chrome ← MV3 extension ← Native Messaging ← mca-native-host.exe → Python native-host
  ↕       отдельные вкладки/роли                    ↕
DeepSeek / Qwen                               ответы на диске
  ↓
веб-редактор ← все авторские ответы → JSON cells → nbformat / Markdown → файл
```

CLI и запущенный Chrome host разделяют SQLite в `%LOCALAPPDATA%\MultiChatAgent\queue.sqlite3`; ответы и служебные данные сохраняются в той же области. `MCA_HOME` меняет её расположение. При регистрации `-McaHome 'C:\Path\McaData'` закрепляет путь для процесса Chrome. Для CLI задайте **тот же** `$env:MCA_HOME = 'C:\Path\McaData'`: изменение переменной только в терминале не меняет окружение уже работающего Chrome.

Native Messaging передаёт UTF-8 JSON с четырёхбайтовой длиной little-endian; stdout host зарезервирован под этот протокол. Очередь захватывается транзакционно. Request ID и сохранённые состояния предотвращают повторную отправку при реконнекте. Неопределённая доставка получает `unknown`/`needs_user_action`; строгое exactly-once для стороннего веб-интерфейса не обещается.

Лимит промпта — 900 KiB UTF-8, исходящего кадра host — 1 MiB, входящего — 8 MiB. Таймаут задания задаётся в секундах, максимум 3600. Сводка задания использует `pending`, `running`, `completed`, `failed`, `timeout`, `needs_user_action`, `unknown`; у отдельных работ есть промежуточное состояние `queued`. Записи и кэш ответов расширения автоматически не удаляются: очистка storage также удаляет защиту от повторной отправки. После перезагрузки Windows продолжите задачу командой `status TASK_ID --wait`; автоматического запуска службы нет.

Разные провайдеры работают параллельно; отправки в одну беседу сериализуются. После тайм-аута/неопределённой доставки беседа изолируется. Для редактора создаётся отдельная роль, даже если он использует тот же сервис, что и автор. Уже открытые пользовательские вкладки не используются для отправки задания. Не редактируйте рабочие вкладки расширения во время выполнения: навигация, закрытие, черновик или лишнее сообщение нарушают принадлежность беседы и приводят к диагностике.

Промпты и ответы хранятся локально без шифрования приложением и отправляются выбранным веб-сервисам. Это учитывается при выборе материалов, которые можно им передать.

## Изменения и поддержка селекторов

| Задача | Где править |
|---|---|
| CSS-селекторы и интервалы провайдеров | Параметры расширения; исходные значения в `extension/src/config.ts` |
| Поиск новых сообщений, отправка, завершение генерации | `extension/src/dom.ts` |
| Владение вкладками, очередь и восстановление worker | `extension/src/engine.ts`, `extension/src/background.ts` |
| Формат плана | `src/multi_chat_agent/models.py`, затем примеры и контракт |
| Планировщик/редактор | `src/multi_chat_agent/scheduler.py` |
| Сборка/валидация документов | `src/multi_chat_agent/assembler.py` |
| Host и framing | `src/multi_chat_agent/native_host.py`, `scripts/native_host_launcher.cs` |

В настройках JSON содержит `providers` без внешней обёртки; checkbox определяет `enabled`. У каждого провайдера есть `selectors`, `stable_ms`, `poll_ms`. Селекторы отдельно описывают `composer`, `send`, `user`, `assistant`, `text`, `generating`, `complete`, `signedIn`, `login`, `captcha`, `quota`, `error`. Начальные значения — кандидаты, которые могут потребовать проверки на реальном DOM. Не заменяйте селектор ответа на весь `body`: можно ошибочно захватить прошлую беседу или элементы интерфейса.

Завершение определяется новым ответом после точного отправленного промпта, маркером окончания, отсутствием индикатора генерации и стабильным непустым текстом. Один истёкший таймер успехом не считается. Если кнопка/роль/маркер изменились, обновите центральный config и mock-страницу с тестом соответствующего поведения; затем выполните сборку и перезагрузите расширение. Значения, ранее сохранённые через параметры, имеют приоритет над обновлёнными defaults — при необходимости восстановите defaults и сохраните.

## Диагностика

| Симптом | Проверка и действие |
|---|---|
| `native host not found` / `connected: false` | Проверьте фактический ID, ключ HKCU, путь manifest и exe. Повторите регистрацию и перезагрузите расширение. Используйте Google Chrome того профиля, где оно загружено. |
| `access ... forbidden` | `allowed_origins` должен точно совпадать с `chrome-extension://ID/`; ID может измениться после переноса распакованного расширения. |
| host сразу отключается | Проверьте `.venv\Scripts\python.exe`, editable-установку, `.venv\native-host\mca-native-host.json`; смотрите stderr/ошибки service worker. stdout нельзя использовать для логов. |
| `provider disabled` | В параметрах отметьте провайдера и сохраните: default `enabled` пуст. |
| Нужен вход / CAPTCHA / квота | Откройте обычную вкладку провайдера и выполните требуемое действие вручную. Повторное задание отправляйте только после проверки состояния предыдущего. |
| Нет `signedIn`, composer или completion marker | Проверьте актуальные селекторы в параметрах; это не исправляется увеличением sleep. |
| CLI ждёт, extension подключён | Убедитесь, что CLI и launcher используют одинаковый `MCA_HOME`; сравните диагностику `doctor` и настройки launcher. |
| `unknown`, `timeout`, `needs_user_action` | Посмотрите сводку, вручную проверьте собственную вкладку задания; не очищайте storage и не пересылайте автоматически. |
| Редактор вернул невалидные cells | Raw ответ сохранён; после одной попытки исправления задача завершается ошибкой. Уточните формат в новом плане. |
| npm/browser test не запускается | Проверьте Node/npm и наличие Playwright Chromium; выполните `npm.cmd ci` и `npx.cmd playwright install chromium` в `extension`. |

Диагностика расширения доступна в параметрах и в **service worker → Inspect** на `chrome://extensions`. Не копируйте тексты ответов и содержимое бесед в Codex для обычной проверки: используйте статусы и пути. Не удаляйте storage расширения ради повторной отправки — это убирает защиту от дублей.

## Локальные проверки

```powershell
& 'C:\Users\User\Documents\ChatGPT\MultiChatAgent\.venv\Scripts\python.exe' -m pytest
Push-Location '.\extension'
npm.cmd test
Pop-Location
& .\scripts\test_installation.ps1
```

`test_installation.ps1` разбирает синтаксис всех PowerShell-скриптов, компилирует exe в изолированном каталоге, проверяет точную передачу нескольких frames (UTF-8, CRLF, длинный payload), EOF, stderr и аргументы Chrome. Также проверяет manifest без BOM, ID validation, установку skill и защиту чужого skill. Используется `-PrepareOnly`: рабочая регистрация HKCU не меняется. Это проверка launcher-процесса, а не свидетельство успешного подключения настоящего Chrome.

## Удаление

Сначала отключите/удалите расширение вручную через `chrome://extensions`, затем:

```powershell
& .\scripts\uninstall_native_host.ps1 -WhatIf
& .\scripts\uninstall_native_host.ps1
```

Удаляется только листовой ключ `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.multichat.agent`; соседние hosts, настройки Chrome, результаты и SQLite не удаляются. Скрипт не удаляет каталоги. Skill и данные можно удалить отдельно вручную, проверив путь и необходимость сохранить ответы. Bootstrap/установка skill не создают фоновые службы и задания планировщика Windows.
