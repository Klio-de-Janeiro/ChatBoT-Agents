# Multi-Chat Agent — Windows MVP

Локальный оркестратор веб-чатов DeepSeek, Qwen, Kimi и Perplexity: Codex составляет план, авторы готовят части материала, отдельный веб-редактор проверяет **все** ответы и возвращает структуру документа. Python собирает `.txt`, `.md`, `.ipynb`, `.json` или `.html`, не выполняя сгенерированный код. Из терминала можно отдельно открыть провайдера, выбрать режимы и отправить одиночный запрос.

Используются открытые пользователем веб-интерфейсы в Chrome; ключи и API чат-ботов не нужны. Авторизация, CAPTCHA и ограничения сервиса остаются под контролем пользователя. При обычной работе Codex получает только JSON-статусы и пути к файлам: содержимое ответов и замечания редактора в его контекст не поступают.

## Статус и границы проверки

Это MVP, а не гарантия совместимости с любой версией сайтов. Локальные тесты проверяют очередь, сборку файлов, протокол и DOM-автоматизацию на mock-страницах. Они не подтверждают успешный реальный запрос DeepSeek/Qwen. Актуальные наблюдения и ограничения провайдеров — в [`extension/PROVIDERS.md`](extension/PROVIDERS.md).

В версии 0.2.1 DeepSeek прошёл живую проверку открытия чата и сохранения ответа CLI. Для Qwen в 0.2.2 добавлен маркер авторизации узкого интерфейса. Управление режимами Qwen в этой раскладке ещё требует проверки. Команда `providers` показывает заявленные возможности адаптеров.

Для живой проверки нужны установленный **Google Chrome**, вручную загруженное расширение, включённые провайдеры и вход пользователя на обоих сайтах. Наличие Edge или Chromium в Playwright не означает установку расширения в реальный Chrome. Скрипты не устанавливают расширение скрытно и не меняют политики Chrome.

## Kimi и Perplexity в 0.2.2

В параметрах обновлённого расширения выберите Kimi или Perplexity и нажмите «Сохранить». Ссылка рядом с названием открывает сайт для входа. Доступны `mca.ps1 open kimi --wait` и `mca.ps1 open perplexity --wait`, а также одноимённые файлы в `launchers`. Для отправки запроса используйте `ask` с тем же ID. Пока эти два адаптера работают с текущими режимами сайта. Для их запросов CLI возвращает ссылку на беседу после появления ответа и ссылки на неё в истории.

Проверка через интерфейс сайтов подтвердила появление тестовых бесед в истории. Сквозную проверку через CLI выполняйте после обновления и включения адаптеров.

Чтобы добавить сервис, внесите его имя, HTTPS-адрес и пути в `src/multi_chat_agent/provider_catalog.json`. Затем добавьте CSS-селекторы под тем же ID в `extension/src/provider-adapters.ts`. Если нужны переключатели режимов, опишите их в `extension/src/mode-controls.ts`. Сборка подставит домены в manifest, а CLI и настройки Chrome автоматически покажут новый сервис. Перед включением проверьте отправку, завершение ответа и появление ссылки в истории на реальном сайте.

## Установка

Нужны Windows, Python **3.11+**, Node.js **20+** с npm, Google Chrome **120+** и .NET Framework 4.x с `csc.exe`. На обычной Windows компилятор доступен в `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` либо в `Framework`. Если он отсутствует, сборка выдаст явную ошибку.

Откройте PowerShell. Во всех примерах путь проекта фиксирован; при переносе замените его целиком:

```powershell
Set-Location 'C:\Users\User\Documents\ChatGPT\MultiChatAgent'
& .\scripts\bootstrap.ps1 -InstallSkill
```

Bootstrap создаёт `.venv`, устанавливает пакет editable и зависимости для разработки, собирает Windows native launcher `.exe`, устанавливает npm-зависимости, собирает расширение, запускает Python/extension/installation tests и устанавливает skill. Python вызывается по абсолютному пути, активация venv не нужна. `npm.cmd` используется для совместимости с PowerShell. Параметр `-Python 'C:\Path\python.exe'` позволяет выбрать интерпретатор, `-SkipTests` пропускает тесты, но не сборку. Bootstrap не регистрирует native host и не загружает расширение в Chrome. Сборка launcher использует `-CompileOnly`: готовый exe появляется в `.venv\native-host`, а конфигурация origin и manifest создаются при регистрации фактического ID ниже; существующая конфигурация при bootstrap сохраняется.

Если browser tests сообщают, что Playwright Chromium не установлен, установите его и повторите bootstrap:

```powershell
Push-Location '.\extension'
npx.cmd playwright install chromium
Pop-Location
```

Это тестовый браузер. Рабочий Chrome установите обычным способом отдельно, если его нет.

### 1. Загрузите расширение в Chrome

1. Откройте `chrome://extensions`, включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение**, выберите `C:\Users\User\Documents\ChatGPT\MultiChatAgent\extension\dist`.
3. Скопируйте ID расширения: ровно 32 строчные буквы от `a` до `p`.
4. Откройте параметры расширения через его значок либо страницу расширений. По умолчанию `enabled: []`: **ни один провайдер не включён**. Отметьте нужные `deepseek` и `qwen`, нажмите **Сохранить**.

Расширение запрашивает `nativeMessaging`, `storage`, `unlimitedStorage`, `tabs`, `alarms` и доступ к сайтам, перечисленным в каталоге провайдеров. `unlimitedStorage` нужен для сохранения ответов и защиты от дублей без стандартного лимита локального хранилища расширения. Настройки селекторов не могут расширить список доменов или добавить исполняемый код.

### 2. Зарегистрируйте native host для фактического ID

Подставьте ID, полученный в Chrome, вместо текста-заглушки:

```powershell
& .\scripts\install_native_host.ps1 -ExtensionId 'ID_ИЗ_CHROME'
```

Скрипт отклоняет любой ID, не соответствующий `[a-p]{32}`. Он компилирует `.venv\native-host\mca-native-host.exe`, пишет конфигурацию и manifest без BOM и создаёт **один** ключ текущего пользователя:

```text
HKCU\Software\Google\Chrome\NativeMessagingHosts\com.multichat.agent
  (Default) = C:\Users\User\Documents\ChatGPT\MultiChatAgent\.venv\native-host\com.multichat.agent.json
```

Manifest разрешает только `chrome-extension://ВАШ_ID/`. Для этого не нужны права администратора. Если этот host уже указывает на другой manifest, установка остановится; `-Force` явно заменяет регистрацию. `-WhatIf` показывает действие без изменений. `-PrepareOnly` собирает exe и manifest, **не меняя реестр**. После переноса проекта или изменения ID повторите регистрацию. Во время пересборки отключите расширение, если Windows сообщает, что exe используется.

Почему `.exe`: manifest указывает на скомпилированный Windows launcher, который запускает абсолютный `.venv\Scripts\python.exe -u -m multi_chat_agent native-host`. Потоки передаются как байты, без декодирования и замены переводов строк; диагностика идёт только в stderr. Аргументы Chrome — origin и `--parent-window` — не передаются парсеру CLI. `.bat`/`.ps1` не используются как native executable; их запуск зависит от shell-механизма и не является проверенным механизмом этого проекта. Требования к регистрации и протоколу описаны в [документации Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).

### 3. Войдите в сервисы и проверьте подключение

1. В том же обычном профиле Chrome откройте [DeepSeek](https://chat.deepseek.com/) и [Qwen](https://chat.qwen.ai/), войдите вручную.
2. Оставьте по авторизованной вкладке каждого нужного провайдера. Расширение использует их для проверки входа, а задания отправляет в активные вкладки собственных отдельных окон Chrome. Не сворачивайте рабочие окна: сайты могут откладывать работу в фоновых вкладках. Одна роль/беседа не смешивается с другой.
3. Перезагрузите расширение на `chrome://extensions`. В его параметрах обновите диагностику: `connected` должно стать `true`. Там же видны фактический `extension_id` и последняя ошибка.
4. Проверьте CLI:

```powershell
.\mca.ps1 doctor
```

`doctor` проверяет локальную среду/очередь и подключённые host-процессы; он не подтверждает актуальность селекторов сайтов или правильность входа в них. Если host не подключён, возвращаются `status: needs_user_action`, `browser_bridge_ready: false`, подсказка `next_action` и код выхода 1. Одного открытия вкладок DeepSeek/Qwen недостаточно: требуется загрузить именно расширение MultiChat Agent и зарегистрировать его native host.

## Работа из терминала

Из корня проекта используйте `mca.ps1`: он передаёт аргументы локальному venv Python без активации окружения. Для запуска из другой директории укажите полный путь к wrapper. Codex skill вызывает абсолютный путь самого интерпретатора.

### Продолжить существующую беседу

1. Откройте беседу из истории сайта и скопируйте адрес из Chrome. Для предыдущего запуска MCA тот же адрес можно взять из поля `jobs[].conversation_url` команды `status TASK_ID`.
2. Передайте адрес через `--chat-url`. Для каждого следующего вопроса используйте ту же ссылку. Если указываете `--task-id` вручную, у каждого нового вопроса должен быть свой ID.

```powershell
$chat = 'https://chat.deepseek.com/a/chat/s/ID_ВАШЕЙ_БЕСЕДЫ'
.\mca.ps1 ask deepseek --chat-url $chat --prompt 'Продолжи с последнего примера.' --wait
.\mca.ps1 open deepseek --chat-url $chat --wait
```

Первая команда дописывает сообщение в эту беседу и сохраняет ответ локально. Вторая открывает беседу для просмотра без отправки сообщения и использует уже открытую вкладку этого сайта, если она есть. Если вкладки нет, Chrome откроет новую. Для этого нужен вход в соответствующий аккаунт и включённый провайдер. Если сайт перенаправил ссылку или прежние сообщения не загрузились, задача остановится до отправки.

В JSON-плане у задания или редактора можно указать поле `"chat_url"`. Для разных ролей используйте разные беседы. Без ссылки первая команда задачи открывает новую беседу. Для этой функции загрузите расширение версии **0.2.4** или новее.


### Список провайдеров и открытие беседы

`open PROVIDER --wait` активирует уже открытую вкладку сайта и оставляет показанный в ней чат. С `--chat-url` команда сначала ищет вкладку с этой беседой. Если такой вкладки нет, она открывает ссылку в существующей пользовательской вкладке выбранного сайта. Если там есть черновик или идёт генерация, команда останавливается. Когда сайт совсем не открыт, команда открывает его в новом окне. Это также относится к файлам запуска из папки `launchers`.


```powershell
.\mca.ps1 providers
.\mca.ps1 open deepseek --wait
.\mca.ps1 open qwen --wait
```

`providers` перечисляет локально поддерживаемые адаптеры и режимы. Первые провайдеры — `deepseek` и `qwen`. Чтобы добавить другой сайт, нужны адаптер, разрешённый домен, конфигурация и тесты; произвольный адрес вместо имени провайдера не поддерживается.

`open` готовит отдельную рабочую беседу в Chrome и при успехе возвращает её `conversation_url` в JSON-сводке. Команда **не отправляет сообщение**, не вызывает редактора и не создаёт ответ или итоговый документ. `completed` означает, что вкладка готова и явно запрошенные режимы проверены; `pending`/`running` означает только продолжающуюся работу. Авторизация и включение провайдера в параметрах расширения нужны так же, как для `ask`. Служебные записи очереди при открытии сохраняются.

Можно сразу задать режимы:

```powershell
.\mca.ps1 open deepseek --think on --search off --wait
.\mca.ps1 open qwen --think off --search on --wait
```

Пример-скрипт `examples\open-provider.ps1 -Provider deepseek -Think on -Search off` вызывает тот же `open` через абсолютный venv Python. Вызов только с `-Provider qwen` сохраняет режимы сайта без изменений. Открытая этим вызовом беседа принадлежит задаче `open`: последующий новый `ask` создаёт собственную беседу, а не дописывает сообщение в открытое окно.

### Отдельная открывашка для каждого провайдера

В папке `launchers` находятся два файла для двойного клика: **`open-deepseek.cmd`** и **`open-qwen.cmd`**. Каждый запускает только свой `open PROVIDER --wait`, без пробного сообщения и без документа. При готовом Chrome bridge расширение активирует уже открытую вкладку выбранного сайта. Сначала нужны bootstrap, регистрация native host, загруженное расширение, включённый провайдер и выполненный пользователем вход; эти файлы не устанавливают расширение и не обходят вход.

Из терминала можно передать те же флаги, что и в CLI:

```powershell
.\launchers\open-deepseek.cmd --think on --search off
.\launchers\open-qwen.cmd --mode think=off --mode search=on
```

Без аргументов режимы сайта сохраняются. Аргументы передаются прямо в CLI: открывашки не разбирают режимы и не подменяют неподдерживаемые значения. Они находят venv относительно своего расположения, поэтому запуск не зависит от текущего каталога терминала. При ошибке остаются видны JSON-диагностика и подсказка; окно ждёт нажатия клавиши, после чего возвращается исходный код ошибки. Отсутствующая venv даёт отдельное указание запустить `scripts\bootstrap.ps1`. Если ожидание истекло или состояние неизвестно, проверьте `status TASK_ID`, прежде чем запускать новое открытие.

Выбран `.cmd`, поскольку Windows открывает его двойным кликом в консоли; для этого не нужно менять PowerShell execution policy. Это пользовательские входы в CLI, **не** native host из manifest: Native Messaging по-прежнему использует скомпилированный `.exe`.

### Прямой запрос

```powershell
.\mca.ps1 ask deepseek --prompt 'Объясни смысл транзакции SQLite на коротком примере.' --wait
.\mca.ps1 ask qwen --prompt 'Составь план изучения SQLite.' --think on --search off --wait
```

Сохранится исходный ответ; stdout содержит только JSON-сводку с состоянием и путём. Редактор в режиме `ask` не вызывается. Пример с параметрами: `examples\direct-ask.ps1 -Provider deepseek -Prompt 'Ваш вопрос'`. Ответ можно открыть самостоятельно по возвращённому пути; skill не читает его в контекст Codex.

Для длинного промпта вместо `--prompt` используйте `--prompt-file 'C:\Path\prompt.txt'` (UTF-8). Параметр `--task-id` задаёт устойчивый ID прямого запроса; без него каждый `ask` создаёт новую задачу.

### Использовать вкладку после открытия

```powershell
.\mca.ps1 open kimi --wait
.\mca.ps1 ask kimi --prompt 'Объясни линейную регрессию' --format ipynb --output '.\results\regression.ipynb' --wait
```

После успешного `open` следующий `ask` того же провайдера использует выбранную вкладку. Если она показывает старую беседу, запрос без `--chat-url` откроет пустую беседу в этой вкладке. Для продолжения старого чата укажите `--chat-url`. Если вкладку перенесли в другое окно, привязка сохраняется, пока URL вкладки не изменился. Chrome активирует вкладку перед отправкой. Начиная с 0.2.7 расширение подключается к уже загруженной вкладке заново после обновления, сохраняя черновик. Разрешение `scripting` используется на доменах подключённых провайдеров.

Если в поле остался черновик, `ask` вернёт `USER_DRAFT`. Чтобы явно заменить старый тестовый текст, добавьте `--replace-draft`:

```powershell
.\mca.ps1 open kimi --wait
.\mca.ps1 ask kimi --replace-draft --prompt 'Объясни линейную регрессию' --format ipynb --wait
```

### Формат файла ответа

Передайте `--format txt|md|ipynb|json|html` и при необходимости `--output`:

```powershell
.\mca.ps1 ask deepseek --prompt 'Разбери пример линейной регрессии.' --format ipynb --output '.\results\answer.ipynb' --wait
.\mca.ps1 ask deepseek --prompt 'Дай конспект.' --format md --wait
```

Если указать только `--output`, CLI определит формат по расширению. При явном формате оно должно совпадать. Если имя без расширения, CLI добавит его. Относительный путь `--output` считается от текущей папки. Без параметров сохраняется прежний `answer.txt`. В JSON-сводке `output_path` указывает на готовый файл, а `jobs[].result_path` — на сохранённый исходный текст.

При одиночном запросе `.ipynb` содержит ответ в одной Markdown-ячейке. Для ноутбука с отдельными ячейками кода используйте план с редактором. JSON содержит массив `cells` внутри объекта, а HTML выводит текст с экранированием разметки. Если файл не удалось записать на диск, CLI сообщает `output_write_failed`, и исходный ответ остаётся по `result_path`.

### Копия ответа в исходном формате нейросети

Начиная с 0.3.0 расширение сохраняет ответ не только как текст: оно забирает его с сайта ровно в том виде, в котором сам сервис отдаёт кнопку «Копировать». Рядом с исходным текстом появляются два файла:

- `responses/<job>.md` — Markdown в диалекте провайдера: заголовки, жирный шрифт и курсив, списки (включая вложенные и чек-листы), таблицы, цитаты, блоки кода с исходным языком и формулы `$...$` / `$$...$$`. Это то же, что попадает в буфер обмена при нажатии «Копировать» на сайте.
- `responses/<job>.content.json` — тот же ответ в виде структурированного дерева блоков (`heading`, `paragraph`, `list`, `table`, `code`, `math`, `image`, `rule`) с `version` схемы. Адреса картинок сохраняются как `src`; сами изображения не внедряются, а их отсутствие не мешает получить ответ.

Исходный `.txt` остаётся главным контрактом (`jobs[].result_path`), поэтому старые сценарии не меняются. В сводке появились пути: `jobs[].markdown_path` и `output_markdown_path`. Если сайт не отдал разметку (или старая версия расширения её не передала), оба поля равны `null`, и всё работает как раньше.

Для прямого запроса публикуемый файл тоже получает Markdown-копию. При `--format md` в `output_path` пишется именно исходный Markdown провайдера (таблицы и блоки кода не превращаются в сплошной текст), а `output_markdown_path` совпадает с `output_path`. При других форматах рядом с артефактом появляется `<имя>.md` с исходной копией.

Скопировать ответ в буфер обмена, не открывая файл, можно командой:

```powershell
.\mca.ps1 copy TASK_ID
.\mca.ps1 copy TASK_ID --raw
```

`copy` пишет в буфер ровно те байты, которые прислал провайдер (Markdown), и печатает только JSON-отчёт с путём и числом символов. `--raw` выбирает сохранённый обычный текст. На Windows используется системный `clip`, на macOS — `pbcopy`, на Linux — первый доступный `wl-copy`, `xclip` или `xsel`; если утилиты нет, возвращается `clipboard_unavailable`, а файлы остаются доступны по путям. Для `open`-задач ответа нет, команда сообщает `no_answer_to_copy`.

Структурированный `content` — основа для будущих генеративных действий: озвучки выбранных блоков и отдельного копирования картинок. Эти поля уже сохраняются, поэтому такие функции не потребуют повторного запроса к сервису.

### Как задаются режимы

Одинаковые флаги доступны у `open` и `ask`:

| Флаг | Запрос к сайту |
|---|---|
| `--think on` / `--think off` | Включить/выключить режим размышления |
| `--search on` / `--search off` | Включить/выключить веб-поиск |
| `--mode NAME=VALUE` | Передать именованный режим; флаг можно повторять |
| Флаг отсутствует | Сохранить текущее состояние сайта |

Например, `--mode think=on --mode search=off` эквивалентно `--think on --search off`. Только `on`/`off` преобразуются в булевы значения, остальные значения `--mode` остаются строками. Поэтому `--mode think=true` не заменяет `--think on`: соблюдайте имя и тип режима из `providers`. Имена состоят из строчных букв, цифр, `_` и `-`, начинаются с буквы, длина — до 32 символов. Допустимо до 16 режимов; строковое значение — непустое, до 100 символов.

Пропущенный флаг не означает `off`. Расширение читает состояние явно указанного переключателя, меняет его только при необходимости и проверяет результат. Конфликт `--think on --mode think=off` отклоняется. Неподдерживаемый режим, отсутствующий элемент управления или неопределимое состояние дают явную диагностику `needs_user_action` **до отправки промпта**. Молчаливой подмены режима и слепого нажатия переключателя нет. Неверный синтаксис флага даёт структурированную ошибку CLI.

Для другого режима сначала проверьте его поддержку через `providers`, затем используйте `--mode NAME=VALUE`. Произвольное имя не создаёт новый режим на сайте. В PowerShell-примерах доступны соответствующие параметры `-Think`, `-Search` и массив `-Mode`, например `-Mode @('think=on', 'search=off')`; без этих параметров флаги вообще не передаются.

### Статус и ожидание

```powershell
.\mca.ps1 status linear-regression-notebook-001
.\mca.ps1 --help
```

`run`/`ask`/`open` сохраняют задание, `--wait` ведёт планировщик до конечного состояния. Без `--wait` запускается отдельный скрытый scheduler-процесс; `status TASK_ID --wait` позволяет дождаться существующей задачи, не создавая новую. `--wait-timeout 30` ограничивает только ожидание CLI: код выхода `3` означает, что задача может продолжаться в фоне. Этот worker не является службой Windows и не запускается автоматически после перезагрузки; возобновите существующую задачу через `status TASK_ID --wait`. При `unknown` или неопределённой доставке сначала проверьте беседу вручную: новый запрос может продублировать сообщение. Переподключение worker/host не является разрешением повторно отправить запрос.

## Формат плана

Формальная договорённость — [`CONTRACT.md`](CONTRACT.md), проверка — `src/multi_chat_agent/models.py`.

| Поле | Значение |
|---|---|
| `task_id` | Уникальный безопасный компонент пути; используйте буквы ASCII, цифры, `_`, `-` |
| `objective` | Общая цель и требования к итоговому материалу |
| `jobs` | Авторские задания: уникальные `id`, `provider`, `prompt`, `depends_on`, `timeout` |
| `jobs[].operation` | `ask` по умолчанию; `open` готовит беседу без сообщения |
| `jobs[].modes` | Запрошенные режимы, например `{"think":true,"search":false}`; по умолчанию `{}` |
| `depends_on` | ID необходимых предшественников; неизвестные ID и циклы запрещены |
| `timeout` | Время задания в секундах; в примерах 180, редактору 300 |
| `editor` | Отдельная роль редактора; для проверенного результата задайте её явно |
| `editor.modes` | Независимые режимы редактора; пропущенные ключи сохраняют состояние сайта |
| `output` | `format` из `txt`, `md` (или `markdown`), `ipynb`, `json`, `html` и `path` к итоговому файлу |

Для воспроизводимого размещения используйте абсолютный `output.path`. Относительный путь считается **от каталога JSON-плана**, а не рабочей директории терминала. В примерах `../results/...` помещает результат в `results` корня проекта. Передача результатов зависимостей и всех ответов редактору выполняется backend, без участия Codex.

В JSON режимы имеют значения boolean или string; `true`/`false` пишутся без кавычек. Документные примеры используют авторские операции `ask`. Для самостоятельного открытия используйте `mca open`: такой тип задачи обходится без редактора и сборки документа, даже если другие задачи создают notebook. Не используйте пробный или пустой `ask` вместо открытия.

Редактор обязан вернуть JSON следующего вида; допустима внешняя ограда ```json:

````text
{"cells":[{"cell_type":"markdown","source":"# Заголовок\nОбъяснение"},{"cell_type":"code","source":"print(1 + 1)"}]}
````

`source` — строка, тип ячейки — `markdown` либо `code`. Не нужны `outputs` и `execution_count`. Для Markdown удобно запросить только Markdown-ячейки. Некорректный ответ сохраняется для пользователя; допускается не более одного запроса исправления формата редактору. Неисправимый ответ означает ошибку, а не успешно созданный notebook. `nbformat` проверяет структуру файла; это не доказательство математической корректности или безопасности кода.

## Skill Codex

Исходник: `.agents\skills\use-chat-bots`. Установка отдельно от bootstrap:

```powershell
& .\scripts\install_skill.ps1
```

Skill появляется в `C:\Users\User\.codex\skills\use-chat-bots`. Перезапустите/обновите чат Codex, если список skills уже был загружен. Пример обращения: «Используй `$use-chat-bots`, подготовь notebook по линейной регрессии: DeepSeek и Qwen — авторы, отдельный Qwen — редактор».

Skill выбирает `open` для открытия без сообщения, `ask` для одиночного запроса либо план с авторами и отдельным редактором для документа. Он вызывает CLI через абсолютный venv Python, читает только сводку и возвращает URL беседы либо ссылку на файл. Содержимое ответов, редакторских замечаний и финального документа он не открывает. Установщик оставляет `.mca-skill-install.json` с путями и признаком владения. Существующий skill без этого признака либо от другой установки не перезаписывается. Для нового местоположения используйте явный `-SkillDirectory`.

## Архитектура и надёжность

```text
Codex → plan.json → Python CLI / scheduler → SQLite command queue
                                              ↕
Chrome ← MV3 extension ← Native Messaging ← mca-native-host.exe → Python native-host
  ↕       отдельные вкладки/роли                    ↕
DeepSeek / Qwen                               ответы на диске
  ↓
веб-редактор ← все авторские ответы → JSON cells → nbformat / Markdown → файл
```

CLI и запущенный Chrome host разделяют SQLite в `%LOCALAPPDATA%\MultiChatAgent\queue.sqlite3`; ответы и служебные данные сохраняются в той же области. `MCA_HOME` меняет её расположение. При регистрации `-McaHome 'C:\Path\McaData'` закрепляет путь для процесса Chrome. Для CLI задайте **тот же** `$env:MCA_HOME = 'C:\Path\McaData'`: изменение переменной только в терминале не меняет окружение уже работающего Chrome.

Native Messaging передаёт UTF-8 JSON с четырёхбайтовой длиной little-endian; stdout host зарезервирован под этот протокол. Очередь захватывается транзакционно. Request ID и сохранённые состояния предотвращают повторную отправку при реконнекте. Неопределённая доставка получает `unknown`/`needs_user_action`; строгое exactly-once для стороннего веб-интерфейса не обещается.

Лимит промпта — 900 KiB UTF-8, исходящего кадра host — 1 MiB, входящего — 8 MiB. Таймаут задания задаётся в секундах, максимум 3600. Сводка задания использует `pending`, `running`, `completed`, `failed`, `timeout`, `needs_user_action`, `unknown`; у отдельных работ есть промежуточное состояние `queued`. Записи и кэш ответов расширения автоматически не удаляются: очистка storage также удаляет защиту от повторной отправки. После перезагрузки Windows продолжите задачу командой `status TASK_ID --wait`; автоматического запуска службы нет.

Разные провайдеры работают параллельно; отправки в одну беседу сериализуются. После тайм-аута/неопределённой доставки беседа изолируется. Для редактора создаётся отдельная роль, даже если он использует тот же сервис, что и автор. Уже открытые пользовательские вкладки не используются для отправки задания. Не редактируйте рабочие вкладки расширения во время выполнения: навигация, закрытие, черновик или лишнее сообщение нарушают принадлежность беседы и приводят к диагностике.

Промпты и ответы хранятся локально без шифрования приложением и отправляются выбранным веб-сервисам. Это учитывается при выборе материалов, которые можно им передать.

## Изменения и поддержка селекторов

| Задача | Где править |
|---|---|
| CSS-селекторы и интервалы провайдеров | Параметры расширения; исходные значения в `extension/src/config.ts` |
| Режимы и их элементы управления | Центральная конфигурация провайдера и DOM-адаптер; не добавляйте слепые клики |
| Список провайдеров CLI | `src/multi_chat_agent/providers.py`; для нового сайта также нужны типы, адаптер и allowlist расширения |
| Поиск новых сообщений, отправка, завершение генерации | `extension/src/dom.ts` |
| Владение вкладками, очередь и восстановление worker | `extension/src/engine.ts`, `extension/src/background.ts` |
| Формат плана | `src/multi_chat_agent/models.py`, затем примеры и контракт |
| Планировщик/редактор | `src/multi_chat_agent/scheduler.py` |
| Сборка/валидация документов | `src/multi_chat_agent/assembler.py` |
| Host и framing | `src/multi_chat_agent/native_host.py`, `scripts/native_host_launcher.cs` |

В настройках JSON содержит `providers` без внешней обёртки; checkbox определяет `enabled`. У каждого провайдера есть `selectors`, `stable_ms`, `poll_ms`. Селекторы отдельно описывают `composer`, `send`, `user`, `assistant`, `text`, `generating`, `complete`, `signedIn`, `login`, `captcha`, `quota`, `error`. Начальные значения — кандидаты, которые могут потребовать проверки на реальном DOM. Не заменяйте селектор ответа на весь `body`: можно ошибочно захватить прошлую беседу или элементы интерфейса.

Завершение определяется новым ответом после точного отправленного промпта, маркером окончания, отсутствием индикатора генерации и стабильным непустым текстом. Один истёкший таймер успехом не считается. Если кнопка/роль/маркер изменились, обновите центральный config и mock-страницу с тестом соответствующего поведения; затем выполните сборку и перезагрузите расширение. Значения, ранее сохранённые через параметры, имеют приоритет над обновлёнными defaults — при необходимости восстановите defaults и сохраните.

## Диагностика

| Симптом | Проверка и действие |
|---|---|
| `native host not found` / `connected: false` | Проверьте фактический ID, ключ HKCU, путь manifest и exe. Повторите регистрацию и перезагрузите расширение. Используйте Google Chrome того профиля, где оно загружено. |
| `access ... forbidden` | `allowed_origins` должен точно совпадать с `chrome-extension://ID/`; ID может измениться после переноса распакованного расширения. |
| host сразу отключается | Проверьте `.venv\Scripts\python.exe`, editable-установку, `.venv\native-host\mca-native-host.json`; смотрите stderr/ошибки service worker. stdout нельзя использовать для логов. |
| `provider disabled` | В параметрах отметьте провайдера и сохраните: default `enabled` пуст. |
| Неизвестный режим / не найден переключатель / состояние не подтверждено | Сверьте имя и тип с `providers`, конфигурацию — с реальным DOM; исправьте настройку либо удалите её только по своему решению. Промпт при такой ошибке отправляться не должен. |
| Нужен вход / CAPTCHA / квота | Откройте обычную вкладку провайдера и выполните требуемое действие вручную. Повторное задание отправляйте только после проверки состояния предыдущего. |
| Нет `signedIn`, composer или completion marker | Проверьте актуальные селекторы в параметрах; это не исправляется увеличением sleep. |
| CLI ждёт, extension подключён | Убедитесь, что CLI и launcher используют одинаковый `MCA_HOME`; сравните диагностику `doctor` и настройки launcher. |
| `unknown`, `timeout`, `needs_user_action` | Посмотрите сводку, вручную проверьте собственную вкладку задания; не очищайте storage и не пересылайте автоматически. |
| Редактор вернул невалидные cells | Raw ответ сохранён; после одной попытки исправления задача завершается ошибкой. Уточните формат в новом плане. |
| npm/browser test не запускается | Проверьте Node/npm и наличие Playwright Chromium; выполните `npm.cmd ci` и `npx.cmd playwright install chromium` в `extension`. |

Диагностика расширения доступна в параметрах и в **service worker → Inspect** на `chrome://extensions`. Не копируйте тексты ответов и содержимое бесед в Codex для обычной проверки: используйте статусы и пути. Не удаляйте storage расширения ради повторной отправки — это убирает защиту от дублей.

## Локальные проверки

```powershell
& 'C:\Users\User\Documents\ChatGPT\MultiChatAgent\.venv\Scripts\python.exe' -m pytest
Push-Location '.\extension'
npm.cmd test
Pop-Location
& .\scripts\test_installation.ps1
.\.venv\Scripts\python.exe .\scripts\test_provider_launchers.py
```

`test_installation.ps1` разбирает синтаксис всех PowerShell-скриптов, компилирует exe в изолированном каталоге, проверяет точную передачу нескольких frames (UTF-8, CRLF, длинный payload), EOF, stderr и аргументы Chrome. Также проверяет manifest без BOM, ID validation, установку skill и защиту чужого skill. Используется `-PrepareOnly`: рабочая регистрация HKCU не меняется. Это проверка launcher-процесса, а не свидетельство успешного подключения настоящего Chrome.

Проверка отдельных `.cmd` входит в `test_installation.ps1`; `test_provider_launchers.py` позволяет запустить её отдельно. Временный подставной executable заменяет Python только в изолированной копии проекта: проверяются выбор провайдера, `open --wait`, передача повторных modeflags и значений с пробелами, пауза при ошибке и сохранение кода выхода. Реальный CLI, Chrome и сервисы в этой проверке не вызываются.

## Удаление

Сначала отключите/удалите расширение вручную через `chrome://extensions`, затем:

```powershell
& .\scripts\uninstall_native_host.ps1 -WhatIf
& .\scripts\uninstall_native_host.ps1
```

Удаляется только листовой ключ `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.multichat.agent`; соседние hosts, настройки Chrome, результаты и SQLite не удаляются. Скрипт не удаляет каталоги. Skill и данные можно удалить отдельно вручную, проверив путь и необходимость сохранить ответы. Bootstrap/установка skill не создают фоновые службы и задания планировщика Windows.
